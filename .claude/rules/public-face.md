> **This is the public-face profile of this repository.** It loads when one of the public
> documents below is opened, and it says who each layer of the documentation is written for and
> in what character, so that an edit is made for its reader and not for its author. It is
> reference, not a task list: nothing here is an instruction to act on right now.

## The layers of the public face

One row per layer. A file belongs to exactly one layer; two audiences in one file is the
God-README pattern this profile exists to catch.

| layer | files or globs | audience | character | language |
|---|---|---|---|---|
| front door | `README.md` | a stranger with an MCP client who develops for, or investigates, a program running in MAME (an arcade board, a home computer); the first thing they read | captivate, then practical, and short: one sentence on what they can do now, the capabilities, the two minutes to a first answer, at least one flow end to end shown in the generated captures, examples as a call and its reply generated by the demos, and a pointer to the index of tools REFERENCE.md generates (never a table typed by hand). The terminal kept apart from the explanation: input and reply in code blocks, prose outside them. No history and no measurement: the WHY of a contract is the reference's | English |
| reference | `REFERENCE.md`, `docs/reference/*.md` | somebody already using the server who comes back for the exact contract of one tool: what it takes, what it refuses, what it returns, and why | reference: complete, precise, scannable, and read one page at a time. `REFERENCE.md` holds the index, the envelope every reply carries and the contract every family shares (the session, names for addresses, a cancelled call); each family of the server's roster has its own page, and on it, per tool, the generated block (call, arguments, reply fields, description), one example from a live run, then the hand-written why. Pages in the roster's order; a family both servers have keeps one name on both. The WHY told as a reason, never as a record: no figure, no date, no "used to" | English |
| contributor guide | `CONTRIBUTING.md` | somebody changing the server: how to run its battery and its live tiers, what proves a change, what the tests hold | practical and short: the commands, what each proves, what a red means. No contract restated: the reference holds it | English |
| demo guide | `demos/*/README.md` | somebody who wants to watch one investigation run end to end on a program they can get legally | practical: what the demo shows, how to get the program, the one command, what the run prints | English |
| demo transcript | `demos/*/TRANSCRIPT.md` | somebody checking what a demo guide claims against every call and reply of the run | reference: generated, complete, never edited | English |

## What is public and what is not

- Public: the documents the layers name, and the captures they show.
- Not public and not this profile's business: `.claude/`, and the fixture READMEs under
  `tests/fixtures/`, read only by whoever touches those doubles.
- Extra READMEs kept public: none.

## Generated documents

| document | generated from | regenerated by |
|---|---|---|
| `REFERENCE.md` and `docs/reference/*.md`, the blocks between their `<!-- scry-reference:begin NAME -->` and `end` markers; `docs/reference/examples.json` | the server's own tool registry (names, descriptions, argument schemas, reply models, roster); the examples from a live run's transcript | `python -m scry_core.reference`, held by this repository's drift test |
| `demos/*/README.md`'s block between `<!-- demo-transcript:begin -->` and `end`, `demos/*/TRANSCRIPT.md` and `demos/*/screen.png` | a run of the demo against the real emulator; the highlights' sentences are the demo's own, on the steps it marks | `demos/<name>/demo.py --update-readme` |

The prose outside the markers is hand-written. A generated block is never edited by hand: a
finding about it is a finding about the tool's code.

## Captures

- This repository generates its own: the captures a document shows are produced by the server
  itself from a script tracked here, never captured by hand.
- Policy: the front door shows at least one flow end to end in them; each demo guide shows its
  program's screen.
- Stale: a capture is stale when the tool or the program it shows changed after it; the script
  is rerun, and a second run reproduces what is committed.

## Limits

- Language: every public document here is in English. This line is the declaration; there is no
  other language rule to cite.
- A public document over 64 KB whose headings also belong to more than one layer is reported as a
  God README with a proposed split; either signal alone is a size or a long file. A front door
  carrying a reference section, or a reference opening with a pitch, is the pattern.
- The front door stays under 16 KB, the generated demo flows included: a section that needs more
  is reference and belongs on a reference page. A flow that grows past it shows fewer steps.
- This server's front door and `REFERENCE.md` carry the same second-level headings in the same order as
  scry-dosbox-x's. A section about something only one emulator has is allowed, by name: DOSBox-X's
  hardware, guest files and debugger channel; MAME's console. Any other section one has and the
  other lacks is a finding.
- The front door closes with the credits line, verbatim, its links resolving; it is attribution
  the project ships, not a leak, and a front door without it is the finding:

  `Developed by Optimiza ([Marcos Hernández](https://www.linkedin.com/in/optimiza/)), in collaboration with [MS-DOS Club](https://msdos.club) and its [podcast](https://www.ivoox.com/podcast-ms-dos-club_sq_f11160693_1.html).`
- The `claude` command, named where it is the program a reader runs (an install command, the
  probe that executes it), is the name of a program and not a mention of the assistant; no other
  use of the name is exempt.
- Nothing else is exempt: a dated measurement, a paragraph about deleted machinery, a note on the
  project's own history, a home-directory path or an assistant's name in a tracked file outside
  `.claude/` is a finding.
